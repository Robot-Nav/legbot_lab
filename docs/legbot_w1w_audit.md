# 四轮足训练与 W1W 部署对照（2026-09-30）

## 项目结构

- `source/robot_lab`：Isaac Lab 的 Legbot 和 Go2 环境、机器人资产配置、观测和奖励。
- `source/rsl_rl`：MoE-CTS 策略、PPO 算法和 runner；学生编码器读取历史观测。
- `scripts/rsl_rl`：训练、播放和 ONNX/TorchScript 导出。
- `deploy/deploy_mujoco`：本地 MuJoCo Sim2Sim。
- `w1w_deploy`：独立实机部署包。

## 训练合理性与后续验证

基础的 50 Hz 控制、腿位置加轮速度动作、特权教师加历史学生结构可以训练轮足策略。原先的接口差异会使实机解释动作和观测错误，因此已优先修正。降低竖直速度惩罚的课程不再降到零，以免鼓励明显弹跳。关节速度限制按实机 RS04 的 15 rad/s 电机上限及小腿 1.4615 减速比收紧。

仍需用真实训练曲线和 Sim2Sim 测试跟踪速度误差、摔倒率、轮打滑、关节饱和与接触冲击。`16384` 个环境和最长 `300000` 次迭代是计算预算上限，不代表收敛已经验证。当前机器有可运行的 PyTorch 与 MuJoCo 环境，已验证纯张量动作/观测辅助函数和 MuJoCo 配置；可用环境中没有完整的 Isaac Lab 训练安装，未执行训练或重新导出。

## 部署问题修复与现场确认

上一轮只读检查发现 30 项测试中有 4 项异常。本轮修复后部署测试 32 项全部通过：

1. 修正控制器重力投影 x/y 的符号，并让训练和 MuJoCo 恢复 Isaac Lab 的标准投影；测试覆盖正俯仰与正滚转。
2. 电机和 IMU 的正式、封装版 systemd unit 及 C++ 程序默认绑定改为 `127.0.0.1`，与本机 UDP 端口设计一致。网页 `8080/TCP` 仍由独立只读服务提供。
3. 生产配置的 CH8 默认值改为文档规定的低位急停。中位或模糊值现在也视为急停。`config_test.yaml` 保留高位急停配置，用于其独立测试场景。
4. 更新过时的配置和 Web 测试预期；Web 将无效电压输出为 JSON `null`，而不是不符合标准 JSON 的 `NaN`。

**现场仍需核实：** 用 `w1wctl elrs-health` 逐档核对 CH8 极性，关机失控保护必须进入急停。安装器会保留已有 `/etc/w1w/controller.yaml`，因此升级后仍应检查实际生效值。现有 ONNX 权重缺少观测语义元数据；重力符号修正后的运动表现必须先在仿真和受支撑机器人上验证，不能仅凭维度和单元测试认定可安全行走。

## 父子连杆碰撞过滤（训练和 MuJoCo）

同一刚体中的组合形状允许重叠，不会彼此产生刚体接触力。不同刚体即使通过关节连接，也应明确设置相邻排除；不能仅用查看器图像或“默认不会碰撞”作为验证依据。

训练 `spawn_legbot` 在创建源机器人之后、外层 clone 复制之前，按 URDF 的 16 个活动关节读取 USD body0/body1，显式写入 `physics:collisionEnabled=false` 和父刚体的 `PhysicsFilteredPairsAPI` 相邻排除。缺少关节或刚体目标时直接报错，避免静默遗漏。URDF 导入 `self_collision=True` 与 articulation 自碰撞设置保持一致，非相邻部件仍参与自碰撞。

MuJoCo `legbot.xml` 增加相同 16 对 `contact/exclude`，不依赖引擎默认的父子过滤。该设置作用于刚体对，覆盖对应刚体上的全部组合碰撞形状。没有全局关闭机器人碰撞或地面碰撞，没有进一步缩小关节处的形状。

验证：使用本机真实 USD 库，测试关节属性写入、仅相邻排除、内部引用复制后的路径重定位、缺失关节报错；连同原有测试共 12 项通过。MuJoCo 关闭默认 FILTERPARENT 后，200 组关节限位内随机姿态没有产生被排除的父子接触，仍能检测非相邻接触；低置机器人也能检测地面接触。随机极限姿态中非相邻碰撞本就可能发生，该检查用于确认过滤范围，不代表这些姿态可执行。

尚未启动完整 Isaac/PhysX 训练；USD 合成测试不等同于实际 URDF 导入、克隆和动力学端到端验证。正式启动时应能看到 `[Legbot] Explicitly excluded 16 adjacent body collision pairs.` 日志；原来已生成/打开的模型需要重新加载新的训练入口。

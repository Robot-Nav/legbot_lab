# W1W 轮足机器狗部署与测试说明

本文档用于在单台 KickPi 上部署和测试 W1W 轮足机器狗程序。当前程序管理
12 个腿部关节电机和 4 个 W190 轮毂电机，参考 `y2_rl7.2` 的 16 自由度策略，
但按当前机器狗的 6 路 CAN/CAN FD 通信方式重新组织。

本文档中的安装流程默认 **只安装，不自动启动任何运动控制**。第一次实机运行必须
逐阶段执行，每完成一步先检查网页、日志和 CAN 状态，再决定是否继续。

## 1. 当前硬件与电机顺序

控制协议中的 16 路电机顺序固定如下，策略输出、命令和反馈都使用这个顺序：

| 索引 | 位置 | 电机 | 总线 | 电机 ID |
|---:|---|---|---|---:|
| 0 | 左前腿 | 髋关节 | can0 | 4 |
| 1 | 左前腿 | 大腿关节 | can0 | 3 |
| 2 | 左前腿 | 小腿关节 | can0 | 2 |
| 3 | 左前腿 | W190 轮毂 | can4 | 1 |
| 4 | 右前腿 | 髋关节 | can1 | 4 |
| 5 | 右前腿 | 大腿关节 | can1 | 3 |
| 6 | 右前腿 | 小腿关节 | can1 | 2 |
| 7 | 右前腿 | W190 轮毂 | can4 | 2 |
| 8 | 左后腿 | 髋关节 | can2 | 4 |
| 9 | 左后腿 | 大腿关节 | can2 | 3 |
| 10 | 左后腿 | 小腿关节 | can2 | 2 |
| 11 | 左后腿 | W190 轮毂 | can5 | 1 |
| 12 | 右后腿 | 髋关节 | can3 | 4 |
| 13 | 右后腿 | 大腿关节 | can3 | 3 |
| 14 | 右后腿 | 小腿关节 | can3 | 2 |
| 15 | 右后腿 | W190 轮毂 | can5 | 2 |

总线参数：

- `can0` 至 `can3`：普通 CAN，1 Mbps。
- `can4`、`can5`：CAN FD，仲裁段 1 Mbps，数据段 5 Mbps，启用 BRS。
- 关节和轮毂命令周期均为 `1429 us`，约 700 Hz。
- W190 的位置、速度和力矩方向不转换，从转子侧看顺时针为正，与 URDF 一致。
- 小腿使用减速比 `1.4615`，方向为 `-1`，换算由电机服务内部完成。

## 2. 主要目录

部署包目录结构：

```text
w1w_runtime/
  controller/       策略控制器、ELRS UDP 客户端、配置和策略模型
  elrs_service/     ELRS 接收机 CRSF 串口解析与本机 UDP 服务
  motor_service/    统一 16 电机 CAN/CAN FD 服务
  imu_service/      DM IMU 服务
  web/              只读网页监控
  scripts/          安装、启动、自检、回滚和打包脚本
  systemd/          6 个 systemd 服务模板
  tests/            离线协议与安全测试
```

安装后的路径：

```text
/opt/w1w/releases/<版本-时间>/   每次安装生成的版本目录
/opt/w1w/current                当前版本软链接
/opt/w1w/previous               上一个版本软链接
/etc/w1w/controller.yaml        机器运行配置，升级时保留
/etc/default/w1w                IMU 与 ELRS 串口配置
```

## 3. 服务组成

| 服务 | 用途 | 是否自动恢复 |
|---|---|---|
| `w1w-can.service` | 配置 can0 至 can5 | oneshot |
| `w1w-motor.service` | 统一控制 12 关节和 4 轮毂 | `Restart=no` |
| `w1w-imu.service` | 读取 `/dev/ttyACM0` 并提供 UDP IMU | 失败后重启 |
| `w1w-elrs.service` | 读取 ELRS 接收机 CRSF 串口并提供本机 UDP | 失败后重启 |
| `w1w-web.service` | 提供 8080 只读监控网页 | 失败后重启 |
| `w1w-controller.service` | 50 Hz ONNX 策略控制 | `Restart=no` |

电机服务和策略控制器都禁止自动重启。这样发生超时或电机掉线后，不会因为 systemd
自动重启而清除安全锁存并突然恢复动作。

## 4. 端口与协议

| 端口 | 协议 | 用途 |
|---:|---|---|
| 55100/UDP | 本机 | 16 电机命令与反馈 |
| 55200/UDP | 本机 | IMU 命令与反馈 |
| 55201/UDP | 本机 | ELRS 16 通道反馈 |
| 8080/TCP | 局域网 | 只读网页监控 |

电机服务正式部署时只绑定 `127.0.0.1:55100`，其他局域网设备不能直接取得电机
主动控制权。

电机命令包固定为 336 字节：

```text
头部 <IHHII>
16 路命令，每路 <fffff>
每路顺序：torque, position, velocity, kp, kd
```

基础反馈 V1 为 356 字节；网页使用 V2 反馈读取轮毂电压。策略控制器仍使用向后兼容
的 V1 协议。

## 5. 默认控制参数

当前参数：

```text
12 个关节：Kd = 5
4 个轮毂：Kd = 1
轮毂阻尼命令：torque=0, position=0, velocity=0, kp=0, kd=1
```

主动控制时：

- 关节使用位置 PD 控制，`Kp=100`、实机安全要求的 `Kd=5`。
- 轮毂使用速度控制，`Kp=0`、`Kd=1`。
- 策略控制周期为 20 ms，即 50 Hz。
- 策略观测为 57 维，历史长度为 4，模型输入共 228 维，输出 16 维动作。

配置文件为 `/etc/w1w/controller.yaml`。首次安装会从
`controller/config.yaml` 创建；以后升级不会覆盖现场配置。

## 6. 安全行为

电机服务启动后立即发送固定阻尼，不会等待网页或策略程序。

进入主动控制前必须满足：

- 16 个电机全部在线；
- 每个电机反馈年龄小于 200 ms；
- 电机服务状态为 `READY`；
- IMU 数据有效且新鲜；
- ELRS 数据有效，CH6 为阻尼、CH8 急停释放、CH9 速度锁定；
- 策略模型完成加载和预热；
- 用户显式确认机器已架空。

以下情况会进入永久阻尼锁存：

- 主动命令超过 100 ms 未更新；
- 任一曾经在线的电机反馈中断超过 200 ms；
- IMU 或 ELRS/CRSF 超时；
- 急停触发；
- 普通关节反馈故障；
- 温度超过配置阈值；
- 策略输出或观测出现 NaN/Inf；
- 策略发送周期超过 80 ms；
- 主动控制权没有在 50 ms 内正确回显确认。

锁存后即使通信恢复也不会自动恢复运动。必须先排除故障、架空机器，再显式重启
电机服务。

W190 的 Byte9 与 V1.2 手册在当前固件上不一致，已观察到正常阻尼时返回 `0x08`。
因此网页只显示 `原始 0xXX`，Byte9 不参与故障判断或安全锁存；W190 是否在线只看
反馈年龄。

## 7. 打包并传到 KickPi

在 Windows 工作目录生成发布包：

```powershell
cd C:\Users\PC\Documents\w1w_deploy\w1w_runtime
python scripts\package_release.py --output ..\w1w_runtime.tar.gz
```

传到 KickPi：

```powershell
scp C:\Users\PC\Documents\w1w_deploy\w1w_runtime.tar.gz kickpi@192.168.0.218:/home/kickpi/
```

在 KickPi 解压：

```bash
cd /home/kickpi
tar -xzf w1w_runtime.tar.gz
cd w1w_runtime
```

## 8. 安装依赖

KickPi 使用 Ubuntu 24.04。先安装依赖：

```bash
sudo apt-get update
sudo apt-get install -y g++ python3-venv python3-pip python3-yaml
```

默认使用 ONNX CPU 推理，独立虚拟环境会安装：

```text
numpy==1.26.4
PyYAML==6.0.2
onnxruntime==1.18.1
```

当前只保留 ONNX CPU 推理，避免部署包中同时维护两套不一致的策略后端。

## 9. 安装程序，但不要启动

安装前确认旧电机进程已经在计划切换时停止。`55100/UDP` 被旧进程占用时，新的基础
服务会拒绝启动。

安装命令：

```bash
cd /home/kickpi/w1w_runtime
sudo W1W_RUN_USER=kickpi ./scripts/install.sh
```

安装脚本会：

1. 在本机使用 `g++` 编译电机、IMU 和 ELRS 服务，并运行 CRSF 解析测试；
2. 创建 `/opt/w1w/releases/<版本-时间>`；
3. 原子切换 `/opt/w1w/current`；
4. 安装 systemd 服务文件；
5. 保留 `/etc/w1w/controller.yaml` 的电机、策略和安全参数；旧 WiFi 字段会原子迁移为
   ELRS 字段，并备份为 `/etc/w1w/controller.yaml.pre-elrs`；
6. 保持所有服务停止，策略服务保持禁用。

检查安装结果：

```bash
readlink -f /opt/w1w/current
systemctl is-active w1w-motor.service w1w-controller.service
```

两个服务都应显示 `inactive`。如果安装结束后电机或策略服务自动运行，不要继续测试。

## 10. 创建策略环境并做离线测试

此步骤加载模型，但不会启动 CAN 服务，也不会发送电机命令：

```bash
sudo W1W_RUN_USER=kickpi /opt/w1w/current/scripts/setup_policy_env.sh
```

期望看到：

- 全部单元测试通过；
- `policy warmup passed`；
- 模型输入形状为 `(1, 228)`；
- 没有 NaN/Inf 错误。

## 11. 第一次启动：只启动基础阻尼和网页

### 11.1 物理准备

启动前必须：

- 将机身可靠架空，四个轮子和四条腿都不能接触地面；
- 准备独立断电开关；
- ELRS CH6 保持阻尼、CH8 急停释放、CH9 速度锁定开启；
- 确认 can4、can5 的 CAN FD 终端电阻和接线；
- 确认没有其他进程占用 55100、55200、55201、8080。

### 11.2 启动基础服务

```bash
sudo w1wctl start-base
sudo w1wctl status
```

这一步启动：CAN 配置、电机固定阻尼、IMU、ELRS、只读网页。不会启动 RL 策略。

### 11.3 查看电机健康状态

```bash
sudo w1wctl motor-health
```

期望结果：

- 状态为 `READY`；
- 16 路电机全部 `online=True`；
- 每路 `age < 200 ms`；
- 普通关节 `fault=0x00`；
- 电机服务控制频率约 700 Hz；
- 轮毂电压和温度合理；
- 没有 `LATCHED`。

`motor-health` 只发送固定阻尼包：关节 `Kd=5`，轮毂 `Kd=1`。

### 11.4 查看网页

浏览器访问：

[http://192.168.0.218:8080/](http://192.168.0.218:8080/)

网页只读，不提供目标位置、速度、力矩或增益控制。检查：

- 四条腿的电机顺序正确；
- 位置、速度、力矩、温度、轮毂电压正常；
- 反馈年龄持续更新；
- 安全状态为 `READY`；
- W190 状态显示为原始十六进制，不把 `0x08` 当过温；
- 静止时速度和力矩没有明显异常跳变。

### 11.5 查看 CAN 错误计数

```bash
watch -n 1 'sudo w1wctl can-status'
```

重点检查 `can4`、`can5`：

- 状态保持 `ERROR-ACTIVE`；
- 不进入 `ERROR-WARNING`、`ERROR-PASSIVE` 或 `BUS-OFF`；
- `bus-errors` 不持续增长；
- `berr-counter tx/rx` 不持续增长。

出现电机离线、持续总线错误或安全锁存时，不要进入策略测试。

## 12. IMU 与 ELRS 验证

```bash
sudo w1wctl health
```

期望：

- 电机状态仍为 `READY`；
- `imu: healthy=True`；
- IMU 数据年龄小于 100 ms；
- IMU 采样率稳定。
- `elrs: healthy=True`，数据年龄小于 500 ms，采样率稳定。

手动缓慢改变架空机身姿态，确认 IMU 方向与 URDF/策略定义一致。方向不正确时不要站立。

IMU 默认配置：

```text
设备：/dev/ttyACM0
波特率：921600
UDP：55200
```

可在 `/etc/default/w1w` 修改设备和波特率。

ELRS 默认配置：

```text
设备：/dev/ttyS6
波特率：420000，8N1
UDP：127.0.0.1:55201
CRSF 数据过期：100 ms
```

先确保策略控制器未运行，再执行：

```bash
sudo w1wctl elrs-health
```

该命令只读取并打印 16 个原始通道，不发送电机主动命令。逐一拨动开关和摇杆，核对：

| 通道 | 程序用途 |
|---|---|
| CH1 | 偏航，程序使用 `wz=-CH1` |
| CH3 | 前后，程序使用 `vx=CH3` |
| CH4 | 横移，程序使用 `vy=-CH4` |
| CH6 | 三档：阻尼 / 站立保持 / RL |
| CH7 | 三档：低速 / 中速 / 高速 |
| CH8 | 急停，默认低位触发 |
| CH9 | 高位开启速度锁定 |

CH8 极性在不同遥控配置中可能相反。默认配置
`network.elrs.emergency_active_high: false` 表示低位急停；若只读实测确认实际为高位急停，
才可改为 `true`。没有核对清楚前禁止启动策略。

ELRS 接收机必须设置失控保护：CH6=阻尼、CH8=急停、CH9=速度锁定。只读阶段关闭
发射机，确认输出进入这些安全值或程序报告 stale。当前服务只解析 CRSF 通道帧；如果
接收机失联后仍持续输出保持值，软件无法仅靠数据年龄识别射频掉线。

## 13. 启动策略，但先保持阻尼

保持 ELRS CH6=阻尼、CH8=急停释放、CH9=速度锁定，然后执行：

```bash
sudo w1wctl controller-start I_HAVE_SUPPORTED_THE_ROBOT
sudo w1wctl logs w1w-controller.service
```

确认字符串 `I_HAVE_SUPPORTED_THE_ROBOT` 是启动主动控制的人工安全门槛。没有这个字符串，
策略服务不会启动。

期望日志：

```text
[preflight] motors ready
[preflight] IMU and ELRS ready; controller remains in damping
[state] DAMPING
```

此时仍不应站立或转轮。若日志直接进入 `HOLDING` 或 `RL_CONTROL`，立即停止测试。

## 14. ELRS 状态与测试顺序

控制器只接受本机 `w1w-elrs.service` 的反馈，并校验请求回显和递增序号。CRSF stale、
ELRS 服务无响应或反馈超时都会永久锁存阻尼；数据恢复也不会继续运动，只能排除故障后
重启电机服务和策略控制器。

### 14.1 站立测试

1. 保持机器架空；
2. 确认 CH6 处于阻尼档、CH8 释放、CH9 锁速；
3. 将 CH6 拨到中档进入站立；
4. 程序先移动到趴下姿态，再平滑移动到默认站立姿态；
5. 逐腿检查方向、零位和关节反馈；
6. 确认轮毂速度保持 0。

过渡过程中每 20 ms 检查遥控状态。急停、通信异常或模式异常会立即发送阻尼并锁存。

### 14.2 姿态保持测试

站立完成后状态为 `HOLDING`。检查：

- 关节没有高频抖动；
- 关节目标与反馈方向一致；
- 关节 `Kp=100`、`Kd=5`；
- 轮毂目标速度为 0；
- CAN 错误计数不增长；
- 网页反馈年龄稳定。

### 14.3 RL 测试

只有站立、方向、IMU 和通信都确认正确后，才能将 CH6 拨到上档进入 RL：

1. 先保持速度锁定，确保速度命令为 0；
2. 将 CH6 从中档拨到上档进入 `RL_CONTROL`；
3. 程序用 0.3 秒平滑接管；
4. 先观察零速度下的姿态稳定性；
5. 再从最低速度档给小幅前进、横移和转向命令；
6. 每次只测试一个方向，并持续观察网页、日志和 CAN 错误计数。

不要第一次测试就把机器放到地面或使用高速档。

### 14.4 正常退出 RL

建议顺序：

1. 速度锁定，等待速度命令归零；
2. 将 CH6 从上档拨回中档，回到 `HOLDING`；
3. 确认当前姿态保持稳定；
4. 将 CH6 从中档拨到阻尼档，平滑移动到趴下姿态；
5. 程序安全释放主动控制并回到 `DAMPING`。

## 15. 急停、停止和重新使能

### 15.1 急停

将 CH8 拨到急停位置。控制器会先尽力发送一帧固定阻尼，然后停止刷新主动看门狗；电机服务
随后进入永久超时锁存。

### 15.2 停止策略

```bash
sudo w1wctl controller-stop
```

如果主动控制已经开始，停止控制器后电机服务预期会进入锁存。不要期待再次启动策略就
能恢复。

### 15.3 清除锁存

只有在故障原因已排除且机器重新架空后执行：

```bash
sudo w1wctl motor-rearm I_HAVE_SUPPORTED_THE_ROBOT
```

该命令会停止策略、清除一次性授权并显式重启电机服务。随后只运行健康检查，不会自动
重新站立或进入 RL。

### 15.4 停止全部服务

```bash
sudo w1wctl stop-base
```

停止顺序为策略、网页、IMU、电机。电机服务退出时会发送 disable 命令，因此只应在
机器人处于可安全卸力状态时停止整个基础栈。

## 17. 状态位说明

电机反馈 `status_bits`：

| 位 | 含义 |
|---:|---|
| 0 | 主动命令超时 |
| 1 至 16 | 对应电机 0 至 15 离线 |
| 17 | 安全锁存 |
| 18 | 等待全部电机在线 |
| 19 | 已就绪 `READY` |
| 20 | 主动运行 `RUNNING` |
| 21 | 因命令超时锁存 |
| 22 | 因电机反馈掉线锁存 |
| 23 | 支持安全释放主动控制 |

网页安全包不会取得主动控制权，也不会刷新主动控制看门狗。

## 18. 常见问题排查

### 18.1 `UDP 55100 is already occupied`

说明旧的 `can_service_wheel` 仍在运行。先确认旧进程来源：

```bash
sudo ss -lunp | grep 55100
ps -ef | grep can_service_wheel
```

确认机器安全后再停止旧进程。不要让两个电机服务同时运行。

### 18.2 状态一直是 `WAITING`

至少一台电机从未在线。运行：

```bash
sudo w1wctl motor-health
```

根据输出的索引和名称检查对应总线、ID、电源和终端电阻。

### 18.3 状态是 `LATCHED`

查看原因：

```bash
sudo w1wctl logs w1w-motor.service
```

常见原因是主动命令超过 100 ms 或曾在线电机反馈中断。先解决根因，再架空机器并运行
`motor-rearm`。不要直接反复重启。

### 18.4 CAN FD 错误持续增加

检查：

- CAN_H/CAN_L 是否使用双绞线；
- 控制器、电机是否可靠共地；
- 总线两端是否只有两个 120 欧终端；
- 支线是否尽量短；
- 1 分 2 是否形成过长星形支路；
- 数据段 5 Mbps 的线长、屏蔽和接插件质量；
- PCAN 固定终端与电机端终端是否重复。

如果错误计数持续增长，不要进入主动控制。

### 18.5 网页显示 W190 `原始 0x08`

这是当前固件已观察到的正常原始值之一，不按 V1.2 手册解释为过温。真实温度单独显示，
在线状态按反馈年龄判断。

### 18.6 网页打不开

```bash
systemctl status w1w-web.service
sudo w1wctl logs w1w-web.service
sudo ss -ltnp | grep 8080
```

网页依赖电机服务，电机服务未启动时网页服务也不会正常工作。

## 19. 回滚

安装新版本后，如果需要切回上一版：

```bash
sudo /opt/w1w/current/scripts/rollback.sh
```

回滚脚本只切换 `current/previous` 链接，不自动重启基础服务。检查版本和配置后，在机器
架空状态下显式执行：

```bash
sudo w1wctl base-restart I_HAVE_SUPPORTED_THE_ROBOT
```

## 20. 当前交付验证

当前本地验证覆盖：

- 336 字节命令和 356/420 字节反馈布局；
- 16 路电机顺序；
- 关节固定阻尼 `Kd=5`、轮毂 `Kd=1`；
- 电机离线和锁存状态位；
- 主动控制权序号回显；
- ELRS 16/70 字节协议、回显、乱序和重放拒绝；
- CRSF 捕获帧 CRC 与 16 通道解析；
- ELRS 服务 stale 和本地 UDP 超时永久锁存；
- IMU 72 字节协议；
- 网页 V2 轮毂电压解析；
- W190 Byte9 原始遥测语义；
- systemd 不自动重启 motor/controller；
- 安装脚本不会启动服务；
- ONNX 模型 228 维输入、16 维有限输出。

第一次实机部署仍必须按照本文第 9 至 15 节逐步执行，不应跳过基础阻尼、网页、CAN
错误计数和 IMU 方向检查。
